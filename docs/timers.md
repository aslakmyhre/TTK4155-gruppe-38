# Timers & PWM — TTK4155

Short oral-exam reference based on the supplied project's `node1/adc.c`, `node2/pwm.c`, `motor.c`, `encoder.c`, and `main.c`.

## What a hardware timer does

A timer/counter peripheral advances from a clock source, often through a **prescaler**. Compare/period registers define events such as **output toggles, PWM edges, or interrupts**. Hardware continues timing without the CPU manually toggling pins.

| Use | Peripheral / source | Configured timing |
|---|---|---|
| **MAX156 ADC clock (Node 1)** | ATmega162 **Timer1 OC1A**, CTC toggle, no prescaler | `F_CPU / (2 × (1 + OCR1A))`; `OCR1A = 0` → **2.4576 MHz** |
| **Motor PWM (Node 2)** | SAM3X8E **PWM channel 0**, 84 MHz clock | `CPRD = 4200` → **20 kHz**; duty limited to 50% |
| **Servo PWM (Node 2)** | SAM3X8E **PWM channel 1**, 84 MHz / 128 | Counter clock **656,250 Hz**; `CPRD = 13125` → **50 Hz** |
| **Encoder position (Node 2)** | SAM3X8E **TC2 channel 0 (TC6)** | Counts external **A/B quadrature transitions**, not a periodic timebase |
| **System tick (Node 2)** | ARM **SysTick** | Interrupt every **1 ms**, increments `msTicks` |
| **PI controller (Node 2)** | **Software scheduling** using `msTicks` | Target **every 10 ms**; no dedicated 10 ms timer ISR |

## PWM: period versus duty

A PWM output has a **period** (how often the waveform repeats) and **duty cycle** (fraction of each period active).

```text
Period:  |<------------- T ------------->|
Output:  ____████████______________________
             high time
Duty = high_time / period
```

For the **DC motor**, period counts are 4200 and duty is updated via `PWM_CDTYUPD`:

```c
uint32_t duty = (4200UL * (uint32_t)percent) / 100;
PWM->PWM_CH_NUM[0].PWM_CDTYUPD = PWM_CDTYUPD_CDTYUPD(duty);
```

In the real code `percent` is first limited, direction is selected, and the absolute value is used. `PWM_CPOL` configures the active polarity. The update register applies a new duty without manually switching the pin.

For the **servo**, the 20 ms period stays constant; **pulse width** communicates commanded position:

| Servo command | High pulse | Duty over 20 ms |
|---|---:|---:|
| `-100%` | 900 µs | 4.5% |
| `0%` | 1500 µs | 7.5% |
| `+100%` | 2100 µs | 10.5% |

`us_to_ticks()` converts microseconds into counter ticks using **64-bit intermediate arithmetic** to avoid overflow.

## SysTick versus peripheral PWM

```c
SysTick_Config(SystemCoreClock / 1000); // 1 ms interrupts
void SysTick_Handler(void) { msTicks++; }
```

The main loop checks elapsed time using expressions like:

```c
if ((msTicks - lastControl) >= CONTROLLER_PERIOD_MS) {
    lastControl = msTicks;
    // update position controller
}
```

This is **cooperative, elapsed-time scheduling**: the timer supplies a clock reference, but other work in the main loop can delay a scheduled update. PWM waveforms themselves are generated by hardware and do not depend on the main loop executing every edge.

## Other timed behaviors

- **Joystick timeout:** 500 ms without a valid frame → stop motor and centre servo.
- **Solenoid:** 50 ms active pulse; 300 ms cooldown, checked using `msTicks` (not a dedicated PWM channel).
- **CAN score:** attempt every 100 ms; **PI debug:** 200 ms; **CAN debug:** 500 ms.

## Oral-exam checkpoints

- **Prescaler?** Divides the source clock before the counter uses it.
- **PWM frequency?** `timer_clock / period_counts` for the PWM configurations above.
- **Duty versus frequency?** Period controls repetition rate, duty controls active fraction.
- **Hardware PWM versus software delay loop?** Hardware drives edges autonomously and gives more stable timing.
- **Timer versus encoder counter?** The quadrature counter counts external position transitions, not elapsed clock ticks.
- **Does 10 ms imply a precise 100 Hz control ISR?** No; this controller is called from the main loop when the elapsed-time condition is met.
