# SPI — Quick Notes (TTK4155 Node 1)

## Overview

**SPI (Serial Peripheral Interface)** is a synchronous, full-duplex serial bus. On **Node 1 (ATmega162)**, the MCU is the master and communicates with:

| Device | Purpose | Chip Select |
| --- | --- | --- |
| MCP2515 | External CAN controller | PB3 |
| OLED | Display | PB1 |
| I/O board | Inputs/outputs | PB2 |

- **SCK**: clock generated by the master.
- **MOSI**: data from master to slave.
- **MISO**: data from slave to master.
- **CS**: selects a device (active low). Devices share the SPI bus, but each has its own CS.


## Initialization (`node1/spi.c`)

```c
SPCR = _BV(SPE) | _BV(MSTR) | _BV(SPR1) | _BV(SPR0);
SPSR = 0;
```
The variables mean

| Bit | Function |
|---|---|
| `SPE` | Activate SPI |
| `MSTR` | Set ATmega162 as master |
| `SPR1` | Clock divider |
| `SPR0` | Clock divider |

This enables SPI in **master mode**, **mode 0**, **MSB first**, with clock **F_CPU / 128** = `38.4 kHz` when **F_CPU = 4.9152 MHz**.

`_BV(bit)` means `(1 << bit)`: a bitmask for a register bit.

### Note Regarding SCL

The clock is not generating at all times. After transfer the clock goes silent again. The SCK-lines value is generally defined by its resting level between transfers, defined by `CPOL` (SPI-mode).

## Transferring One Byte

```c
uint8_t spi_transfer(uint8_t value)
{
    SPDR = value;                      // Start transfer
    while (!(SPSR & _BV(SPIF))) {}    // Poll completion flag
    return SPDR;                      // Received byte
}
```

- **SPDR**: SPI data register (write to transmit; read to receive).
- **SPSR**: SPI status register.
- **SPIF**: transfer-complete flag.
- SPI transfers **8 bits in both directions simultaneously**. The received byte is *not necessarily* the same as the transmitted byte.
- This implementation uses **polling**, not interrupts or DMA, for byte transfers.

For Atmega162 `SPDR` works as an interface against the SPI-hardware. Internally the SPI-peripheral contains a shift register and buffering. Writing

```c
SPDR = 0x42;
```

Is loading data that is to be sent. When the data is transfered you read the same register. Its the same register address in **C**, but there exist different internal data paths for sending and receiving.

### Sending Dummies

When trying to read a register from the `MCP2515` we use

```c
spi_select(SPI_SLAVE_CAN);

spi_transfer(0x03);     // READ command
spi_transfer(address);  // Register address

uint8_t value = spi_transfer(0x00);

spi_deselect_all();
```

This is done due to the `SPI Master` having to generate **8** clock cycles for tranfering the 8 bits from `MCP2515` to the `Atmega162`. Therefore sending `0x00` will generate these clock pulses. At the same time `MCP2515` is sending the requested register value over the `MISO`-line.

On the line when we are reading the `value` with `spi_transfer(0x00)`, the dummy bits are send from `Armega162` to `MCP2515` over `MOSI`, while it is receiving the register values on `MISO`.

Also remember that `CS` is held `LOW` during the entire transaction.


## Selecting a Device

```c
spi_select(SPI_SLAVE_CAN); // Set MCP2515 CS low
// ... SPI transfers ...
spi_deselect_all();        // Set all CS pins high
```

Internally, selection clears the chosen bit in `PORTB`:

```c
PORTB &= (uint8_t)~_BV(cs_pins[slave]);
```

This is a **read–modify–write** operation: clear one bit, preserve the others.

## Example: Read an MCP2515 Register (`node1/mcp2515.c`)

```c
spi_select(SPI_SLAVE_CAN);
spi_transfer(0x03);        // MCP2515 READ instruction
spi_transfer(address);     // Register address inside MCP2515
uint8_t value = spi_transfer(0x00); // Dummy byte clocks data back
spi_deselect_all();
```

Unlike a **memory-mapped MCU register** (e.g. `TC2->TC_BMR` on Node 2), an **external MCP2515 register** cannot be accessed directly by a CPU memory address. We transmit an instruction and register address over SPI.

## System Connection

```text
Node 1 (ATmega162) --SPI--> MCP2515 --CAN bus--> Node 2 (SAM3X8E)
                   \-----> OLED
                   \-----> I/O board
```
