Block diagram of the two-node ping-pong system

Two microcontrollers share one CAN bus. Node 1 reads the controls and draws the menu; node 2 moves the motor, servo and solenoid and counts goals. Figure 1 shows what the system does. Figures 2 and 3 place all 170 functions of the two firmware images in their source files (109 on node 1, 61 on node 2) and show which file calls which.

KEYHow to read figures 2 and 3

  • One source file, with every function it defines
  • Hardware outside the firmware
  • Source file that is not part of the build
  • Function other files can call
  • File-local function (static)
  • Interrupt handler
  • Defined but never called
  • Prints debug text to the UART through stdio
  • Function call, labelled with the functions called
  • Hardware access: pin, bus or memory-mapped address
  • Joined lines. Lines that cross without a dot are not connected
  • CAN bus

NOTECode that is present but not wired in

  • node2/time.c (18 functions) is not listed in the node 2 Makefile. It defines its own SysTick_Handler, which main.c also defines, so the two cannot be linked together.
  • can_tx and uart_flush on node 2 and io_board_info on node 1 are defined but never called.
  • node1/tools/plot_adc.py runs on the PC and plots the ADC lines that print_adc_values prints; its functions are listed in the PC block of figure 2.
